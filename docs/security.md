# 数据、安全与使用边界

## 个人工作区

应用默认面向本机单用户，没有独立账号和行级数据隔离。Compose 绑定 `127.0.0.1`，数据库仅保存在服务端。可选 `APP_ACCESS_TOKEN` 为整个工作区增加一道共享口令；前端在设置中保存它并随 API 请求发送。任何拥有口令的人都能访问同一份资料。浏览器本地存储不是安全保险箱，使用后应关闭共享设备上的会话或清除口令。

公网部署请自行提供 HTTPS、访问控制、网络限流、备份策略和运行监控。不要仅改变监听地址就直接开放私人资料。模型服务地址属于管理员配置，应由可信操作人员设置。

## 数据流向

| 操作 | 数据流向 |
| --- | --- |
| 文本导入 + 演示模式 | 正文送到自己的后端并保存在 SQLite，不发送模型服务 |
| 链接导入 | 自己的后端向公开文章网站发起请求并保存提取文本 |
| AI 摘要 | 文章内容与任务提示发送到配置的模型服务 |
| AI 追问 | 文章内容、问题及所需对话上下文发送到模型服务 |
| AI 对比 | 选中文章内容与任务提示发送到模型服务 |
| JSON 备份 | 浏览器下载主题、原文、摘要、对话和对比记录 |

模型服务的日志、保留期限和费用由服务商决定。应用不声称模型输出已经事实核查。只有你有权处理的内容才应导入。

## 网页与模型输入

网页抓取器仅接受 HTTP(S)，限制超时、重定向及响应体积。每个跳转目标都应校验，拒绝私有、回环、链路本地、保留与非全局地址，以降低服务端请求伪造风险。抓取不使用用户浏览器的 Cookie，不绕过登录或付费墙。

文章和网页中出现的指令均为不可信内容。AI 提示词将文章视为待分析材料，并要求提供原文依据；这可以降低提示注入影响，无法保证模型绝不会受其影响。前端用文本节点显示文章和模型输出，避免将它们作为 HTML 执行。

## 备份与删除

界面的 JSON 导出是首选可移植备份。请妥善保管备份文件；其中包含原文和个人提问。导入前先导出现有数据，阅读导入完成提示后再删除源文件。

SQLite 运行时可能存在 WAL / SHM 辅助文件；直接拷贝数据库前应停止服务，或使用 SQLite 备份机制。不要在运行中只复制主文件并假设它完整。

删除文章、主题和容器卷是不同操作：删除主题保留文章，删除文章移除该文章记录，删除 Docker 命名卷会删除整个数据库。应用不提供回收站，恢复依赖你自己的备份。
