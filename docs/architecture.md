# 架构与开发约定

## 运行结构

浏览器通过同源 `/api/*` 请求访问 FastAPI。FastAPI 同时提供 `frontend/` 静态资源，因此开发和部署都只需一个服务。SQLite 存储主题、原文、摘要、对话和对比历史。AI 密钥只存在服务端配置中。

```text
浏览器 ── HTTP ── FastAPI ── SQLite
                    ├── 安全网页抓取 / 正文提取
                    └── AI 适配器 ── OpenAI 兼容聊天服务
```

前端无需构建。修改 `frontend/` 后刷新即可；后端开发可在启动命令中加 `--reload`。单个 SQLite 文件适合个人使用。进程重启、浏览器刷新与容器重建均不依赖浏览器内存恢复文章。

## 数据约定

- 每个实体使用服务端分配的 ID，时间使用 UTC ISO 8601。
- 文章正文保留原始可读文本；空行分段，从 `[p1]` 开始定位证据。
- 摘要是结构化 JSON：`core_points`、`arguments`、`author_stance`、`insights`、`caveats`。
- 对话属于一篇文章，按创建顺序返回。模型请求以当前文章为上下文，不自动混入其他文章。
- 对比属于主题，保存参与文章 ID 与生成结果，便于回看。
- 结果保存 `mode`，以便区分演示内容和真实模型输出。
- 删除主题只解除文章关联；删除文章会移除相应对话。备份应在删除前导出。

## 模型适配

`AI_MODE=auto` 只根据是否有服务端密钥选择模式；已经选择 AI 后，网络错误、鉴权失败和非法输出都会明确报错。用户可以重试；不会把失败伪装成本地摘要成功。

AI 摘要和对比要求返回符合固定结构的数据。后端应验证结果结构再写入。文章内容作为不可信输入；提示词要求忽略其中对系统或工具的指令。段落引用使读者能够核对模型依据，并不保证模型判断正确。

演示适配器使用本地段落抽取和模板，保留真实操作链路；它的输出必须带演示标识。开发新模型适配器时应保持返回结构不变，避免让前端适配服务商细节。

## 错误与事务

API 失败返回非 2xx 状态和 `detail`。用户可修正输入、切换正文导入或重试模型生成。外部网络请求应有超时和最大输入 / 响应体积。

写入数据使用事务，查询使用参数化语句，开启 SQLite 外键约束和忙等待。备份导入应整体校验、原子提交，避免半份备份污染工作区。不要把模型请求放在长时间占用写锁的事务中。

## 继续开发的方向

1. 多人使用前加入身份认证、所有权字段与每条查询的权限约束。
2. 更大规模数据可引入正式迁移工具、PostgreSQL、后台任务队列。
3. 长时间批处理可增加任务状态与取消，不让浏览器连接承担全部生命周期。
4. 检索扩展应先定义引用、索引更新和删除语义，再加入向量库。

修改接口时同步更新 `docs/api.md` 和端到端流程测试。禁止把密钥、真实数据库或私人备份提交到版本库。
