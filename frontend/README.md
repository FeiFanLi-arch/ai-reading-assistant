# 前端开发说明

前端由 FastAPI 同源托管，无需 Node.js、打包器或 CDN。浏览器入口是 `/`，静态资源挂载在 `/static`。

- `index.html`：应用外壳、主导航容器、原生对话框和通知区域。
- `styles.css`：颜色变量、桌面工作台布局、文章/对话组件及响应式样式。
- `app.js`：DOM 工具、API 客户端、hash 路由、文章库、主题对比、阅读与追问、弹窗和导入导出。

修改文件后刷新页面即可。开发服务启动方式见项目根目录 README。可使用 `node --check frontend/app.js` 做独立语法检查。

## 约定

1. API 请求统一经过 `api()`，传递可选的 `X-Access-Token`，处理结构化错误；模型密钥不进入前端。
2. 用户输入和模型输出通过 `el()` / `citedText()` 写入文本节点。不要对这些内容使用 `innerHTML`。唯一的 SVG `innerHTML` 来自文件内固定的图标常量。
3. 使用 `replace()` 设置容器内容，它会展开节点数组并过滤空值，避免原生 `replaceChildren()` 将数组或布尔值转成可见文字。
4. `renderId` 防止旧页面的异步响应覆盖新页面；列表搜索额外用请求序号防止乱序覆盖。
5. hash 路由不依赖服务器重写。文章和主题状态在服务器 SQLite 中持久化；本地存储只保存应用访问令牌。
6. `[pN]` 引用可跳转至当前文章原文。段落按空行切分，与后端规范化方式一致；模型给出不存在的段落编号时会提示核对。
7. 页面上的模式标签表示服务器配置。真实模型可用性以摘要、对话或对比请求的结果为准。历史列表按最近更新时间显示，摘要重试、追问、编辑和收藏等操作可能更新排序。

继续扩展时，优先将页面功能拆成原生 ES 模块，再引入构建工具。服务端响应契约见根目录 API 文档，新增字段应同步更新各视图与 Markdown/JSON 导出逻辑。
